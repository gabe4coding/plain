## acceptance (every PR)
- one intent per PR, own branch `harden/<slug>` from fresh origin/main, squash-merged by lead with `gh pr merge --squash --admin --delete-branch`.
- bug fixes: a test that fails on origin/main and passes on branch. show red output in PR evidence.
- new gate: show it fails on a planted violation (paste output), then passes on clean tree.
- `node scripts/validate.mjs` passes on HEAD (pr-gate hook needs it). CI `test` + `live` green.
- never weaken a gate (CODING_STANDARDS.md "Tests"). no lower threshold, no changed expected output, no skip.
- docs follow code (CODING_STANDARDS.md "Docs that follow the code"); writing-docs skill for user docs; writing-agent-notes skill for notes.
- PR body via puredori:pr-write: `## Intent`, `## Evidence` (real output), `## Story` row. attribution line from repo rules.
- no literal credentials; no remote sites in e2e.

## crew + review (lead decides, per user)
- lead: plans, builds shared parts (P0), dispatches, runs exit checks itself, merges. only lead writes this file.
- builder: one subagent per PR, `isolation: worktree`, model opus. lane = files listed for its PR; touch nothing else except imports a rename forces.
- review per PR, in order:
  1. builder: validate.mjs + `code-review` skill on own diff, fix confirmed findings.
  2. CI green, read by lead with `gh pr checks <n> --watch`.
  3. fresh reviewer subagent (gets this file + PR number, not lead reasoning). returns confirmed findings with file:line + failing scenario.
  4. risk PRs (marked R below): second reviewer with another model: `codex exec review --base origin/main` in PR worktree.
  5. confirmed high/med finding -> builder fixes -> validate + CI again. re-review only if fix changed behavior.
  6. merge when CI green and no open confirmed high/med finding. rebase on main first if behind; CI again.
- concurrency: max 4 builders at once, lanes disjoint. merge in table order inside a wave.
